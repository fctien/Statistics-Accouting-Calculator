## 0. 目的與成功條件

### 0.1 目的

1. 做一個仿 BA II Plus Professional 的**財務／會計計算 PWA**，手機與電腦都能用、可離線
2. 把整個開發過程變成**教學案例**：從 CLAUDE.md 設定 → 下 Prompt → 驗收，一步一步帶學生做出來

### 0.2 成功條件

| # | 條件 | 驗收方式 |
|---|---|---|
| S1 | 每個工作表的結果與 TI 官方手冊範例、Excel 公式一致 | `pytest` 全過；golden 值附出處 |
| S2 | 同一份 Python 引擎在 CPython 與 MicroPython 都算出相同結果 | `pytest` 與 MicroPython 雙執行環境 golden 測試全綠 |
| S2b | 手機開啟 App 立刻看到畫面；Python 就緒前可先輸入 | 實機量測：殼顯示 < 1 秒、Python 就緒時間記入 log |
| S3 | 手機（Android Chrome／iOS Safari）可安裝成 App、斷網可用 | 實機安裝＋飛航模式操作 |
| S4 | 資料只存本機；可匯出／匯入 JSON；可選擇同步 Google Drive | e2e 來回測試（匯出 → 清空 → 匯入 → 值相同） |
| S5 | 算不出來時明確說明原因，絕不顯示「看起來正常的錯數字」 | 錯誤情境測試（IRR 無解、除以零、N 非正數…） |
| S6 | 兩份教材（AI Agent 版、EMBA 版）＋兩份 Prompt 卡，每個步驟都有對應 git tag 可接手 | 教材自測：卡片中的驗收指令在對應 tag 上可執行 |

### 0.3 不做（YAGNI）

- 不做帳本／分錄記帳系統（那是 MoneyBook 的範圍）
- 不做 OneDrive／Dropbox 專屬 API（用 JSON 匯出存到任何雲端資料夾即可）
- 不做多人共用、登入帳號、伺服器端儲存
- 不做三角函數／雙曲函數鍵（BA II Plus 有，但會計用途低）；保留 `ln`、`eˣ`、`yˣ`

## 1. 架構

### 1.1 技術選擇（已決定）

- **MicroPython（WebAssembly 版）** 在瀏覽器執行 Python 計算引擎 → 純靜態檔、可部署到 GitHub Pages、可完全離線
- 介面用原生 HTML／CSS／少量 JavaScript（不用框架，教學上好讀）
- 執行環境檔案鎖定確切版本（pinned），**放進 repo 一起部署**（`web/vendor/`），不依賴 CDN

#### 為什麼不用 Pyodide（2026-10-20 實測 jsDelivr 傳輸大小）

| 執行環境 | 檔案 | 原始 | 傳輸（壓縮後） |
|---|---|---|---|
| Pyodide 0.28.3 | `pyodide.asm.wasm`＋`python_stdlib.zip`＋js | 約 12 MB | 約 5.3 MB |
| MicroPython 1.29.0（`@micropython/micropython-webassembly-pyscript`） | `micropython.wasm`＋`micropython.mjs` | 約 0.56 MB | 約 0.23 MB |

Pyodide 除了下載量大，首次還要編譯 8.6 MB wasm 並解開標準函式庫，中低階手機啟動慢；MicroPython 約小 23 倍

#### 共用載入優化（不論執行環境都做）

1. **殼先顯示（app shell）**：HTML／CSS／JS 由 Service Worker 快取，開啟即顯示，不等 Python
2. **Web Worker 背景載入**：Python 執行環境在 Worker 中載入，介面不卡；就緒前按「計算」的請求進佇列，就緒後自動算出；畫面顯示載入狀態
3. **安裝時預先快取（precache）**：Service Worker `install` 階段即快取執行環境與引擎檔，第二次起完全離線
4. **啟動計時**：記錄「殼顯示」與「Python 就緒」兩個時間點，顯示在設定頁的「關於」區，並寫入驗證 log

#### 退路（fallback）

- M2 第一件事是 **spike**：在 MicroPython WebAssembly 版驗證浮點數為**雙精度（IEEE 754 double）**，並確認 `math` 模組需要的函式（`log`、`exp`、`pow`、`sqrt`、`isfinite`、`factorial` 或自行實作）
- 判定方式：`1e300 * 10` 不為 `inf`、`0.1 + 0.2 == 0.30000000000000004`、`sys.float_info`（若有）或 `struct.pack('d', ...)` 長度 8、TVM golden 測試誤差 < 1e-9
- **不符就退回 Pyodide**（保留上述共用優化），並在 DEVLOG 寫明原因；引擎因為是可攜子集，不需改寫

### 1.2 MVC 分層

```
┌──────────── View（web/index.html, css/, js/views/*.js）───────────┐
│  表單、表格、紙帶、設定頁；只負責顯示與收集輸入                    │
└───────────────▲──────────────────────────────┬────────────────────┘
                │ 結果（dict → JSON）           │ 使用者事件
┌───────────────┴──── Controller ──────────────▼────────────────────┐
│  js/app.js：路由、事件、經 Web Worker（js/py-worker.js）呼叫 bridge│
│  engine/bridge.py：唯一對外入口 call(worksheet, action, payload)   │
└───────────────▲──────────────────────────────┬────────────────────┘
                │                               │
┌───────────────┴──── Model（engine/*.py，純 Python，無 I/O）───────┐
│  tvm / amort / cashflow / iconv / stats / bond / depr / business   │
│  / calc / memory / fmt                                             │
└────────────────────────────────────────────────────────────────────┘
Storage（js/storage/*.js）：IndexedDB ⇄ JSON 匯出入 ⇄ Google Drive（選用）
```

- **Model 不依賴瀏覽器**：可以在電腦上直接 `pytest`，也可以在 MicroPython 裡跑
- **可攜子集（portable subset）**：引擎只用 CPython 與 MicroPython 都支援的功能
  - 可用：`math`、`json`、基本型別、函式、類別、f-string、例外
  - 不用：`decimal`、`datetime`、`fractions`、`dataclasses`、`typing` 的執行期功能、`functools.lru_cache`、第三方套件
  - 由 `tools/check_portable.py` 掃描 `engine/` 的 import 與語法，違規就失敗
- **bridge.py 統一回傳格式**：

```json
{"ok": true,  "values": {"PMT": -599.55}, "display": {"PMT": "-599.55"}, "warnings": []}
{"ok": false, "error": "IRR 無解：現金流沒有正負號變化", "field": "CF"}
```

## 2. 功能規格

### 2.1 共通的人性化輸入規則

1. **留空求解**：工作表中留一格空白，按「計算」就解那一格；留兩格以上空白時提示「請只留一格空白」
2. **現金流方向**：TVM／CF 用「收到 ↓／付出 ↑」切換，內部轉成正負號；同時顯示 TI 的正負號慣例，讓學生能對照實體計算機
3. **欄位說明**：每個欄位有中文名稱＋英文縮寫（例：每期付款 PMT），點 ⓘ 顯示說明與範例
4. **輸入容錯**：接受 `1,000`、`1000`、`1e3`、`5%`（轉 0.05 或 5，依欄位定義）；格式錯誤時欄位標紅並說明
5. **即時驗證**：例如 P/Y 必須大於 0、N 必須大於 0
6. **儲存情境**：每個工作表可以把目前輸入存成具名情境（例：「房貸 30 年」），之後可以載入
7. **鍵盤操作**：電腦上 Enter 計算、Tab 換欄、Esc 清除；手機上叫出數字鍵盤（`inputmode="decimal"`）
8. **匯出**：表格類結果（攤還表、折舊表、CF）可以匯出 CSV；任何結果都可以一鍵複製

### 2.2 工作表

| 工作表 | 輸入 | 輸出／可求解 | 備註 |
|---|---|---|---|
| **計算機 CALC** | 算式字串 | 結果、紙帶 | 支援 `+ − × ÷ ( ) % √ x² 1/x yˣ ln eˣ n! nPr nCr`、`ANS`；用安全解析器（AST 白名單），**不用 `eval`** |
| **記憶 MEM** | — | M0–M9 | `STO n`、`RCL n`、`M+`、`M−`、`M×`、`M÷`；累加器顯示 Σ 與筆數 |
| **TVM** | N、I/Y、PV、PMT、FV、P/Y、C/Y、BGN／END | 任一個 | I/Y 用牛頓法（Newton），失敗時改用二分法（bisection）；無解時回報原因 |
| **AMORT** | 沿用 TVM、P1、P2 | BAL、PRN、INT；完整攤還表 | 最後一期的尾差要明確標示 |
| **CF** | CF0、C01…Cnn、F01…Fnn、I、RI（再投資率） | NPV、IRR、NFV、PB、DPB、MIRR | 現金流有多次正負號變化時警告「IRR 可能有多個解」 |
| **ICONV** | NOM、EFF、C/Y | NOM ↔ EFF | 雙向即時換算 |
| **STAT** | X、Y 資料表；模式 1-V／LIN／Ln／EXP／PWR | n、x̄、Sx、σx、ȳ、Sy、σy、a、b、r、Σx、Σx²、Σy、Σy²、Σxy、預測 X'／Y' | Sx 用 n−1、σx 用 n（與 TI 相同） |
| **BOND** | SDT、CPN、RDT、RV、ACT／360、2/Y／1/Y、YLD 或 PRI | PRI、YLD、AI | 規則依 TI 手冊；golden 值必須取自手冊範例 |
| **DEPR** | SL／SYD／DB／DBX、LIF、M01、DB%、CST、SAL、YR | 各年 DEP、RBV、RDV；完整折舊表 | DBX 在直線法較有利時自動轉換 |
| **商業** | — | — | 包含下面五項 |
| 　PROFIT | CST、SEL、MAR／MU | 任一個 | 毛利率（margin）與加成率（markup）兩種都有 |
| 　BRKEVN | FC、VC、P、PFT、Q | 任一個 | |
| 　Δ% | OLD、NEW、%CH、#PD | 任一個 | #PD > 1 時是複利成長 |
| 　DATE | DT1、DT2、DBD、ACT／360 | DBD 或任一日期 | 顯示星期；日期用自寫的序數日（ordinal）演算法，不用 `datetime` |
| 　稅務 | 金額、稅率、內含／外加 | 未稅、稅額、含稅 | 預設營業稅 5%；另有扣繳、二代健保補充保費等預設，**稅率實作時查證並附官方連結**，可在設定中修改；金額以「分」整數計算 |
| **設定 FORMAT** | 小數位數 0–9 或浮動、千分位（`1,000.00` 或 `1.000,00`）、日期格式（US／EUR）、運算順序（AOS／Chain）、深色模式、稅率預設 | — | 即時預覽 |

### 2.3 數值規則

1. 引擎內部用 Python `float`（雙精度，M2 spike 驗證）；**只在顯示時**依設定四捨五入
2. 稅務與金額合計以「分」為單位的**整數**計算（MicroPython 沒有 `decimal`）；四捨五入規則為四捨五入到分、負數對稱（half away from zero），由 `engine/money.py` 統一提供，不各自實作
3. 日期以「自 0001-01-01 起的序數日」整數表示，提供 `to_ordinal`／`from_ordinal`／`weekday`，閏年規則用格里曆（Gregorian）
4. 疊代求解（I/Y、IRR、YLD）的收斂條件：|f(x)| < 1e-10，最多 200 次；未收斂回傳錯誤，不回傳最後一次猜測值
5. **任何算不出來的情況回傳 `ok: false` 加上原因**，不用 0、不用預設值、不猜

## 3. 儲存與雲端

### 3.1 本機（IndexedDB）

| Store | 內容 |
|---|---|
| `settings` | 顯示設定、稅率、雲端設定 |
| `scenarios` | 各工作表的具名情境 `{id, worksheet, name, inputs, updated_at}` |
| `tape` | 計算機紙帶（最多 500 行，超過時捨棄最舊的） |
| `memory` | M0–M9、累加器 |

### 3.2 JSON 匯出入

```json
{"app": "BACalc", "schema": 1, "exported_at": "2026-10-19T10:00:00+08:00",
 "data": {"settings": {}, "scenarios": [], "tape": [], "memory": {}}}
```

- 匯入前先驗證 `app` 與 `schema`；不合格就拒絕並說明原因
- 匯入方式可選「合併」或「取代」；選取代時要先確認
- 使用者可以把檔案存到任何雲端資料夾（OneDrive、Dropbox、iCloud…）

### 3.3 Google Drive 同步（選用，預設關閉）

- 用 Google Identity Services 的 token client，權限範圍（scope）只要 `drive.appdata`（App 專屬隱藏資料夾，看不到使用者其他檔案）
- 檔名 `bacalc-backup.json`；動作有「上傳」、「下載」、「比較時間」
- 衝突處理：雲端檔案比本機新時，**不自動覆蓋**，顯示雙方時間讓使用者選擇
- **需要你親自做**：在 Google Cloud Console 建立 OAuth Client ID，並把部署網址加進授權來源；申請步驟寫在 `docs/google-oauth-setup.html`
- Client ID 在設定頁輸入，存在本機（不寫死在程式碼裡）

## 4. 測試計畫

| 層級 | 工具 | 內容 |
|---|---|---|
| 1. 引擎單元測試 | `pytest` | 每個工作表至少 3 題 golden 值（出處：TI Guidebook 範例頁碼，或 Excel 公式＋儲存格輸入）；外加錯誤情境 |
| 2. 突變測試 | `tools/mutate.py`（自寫） | 故意改壞公式（例如把 BGN 因子拿掉），測試必須失敗；至少 15 個突變 |
| 3. MicroPython 雙執行環境 | `tools/run_mpy_golden.mjs`（Node）＋`web/selftest.html`（瀏覽器） | 同一份 golden JSON 在 MicroPython 逐題比對；CPython 與 MicroPython 結果差異 > 1e-9 即失敗 |
| 3b. 可攜性 | `tools/check_portable.py` | `engine/` 不得 import 子集以外的模組 |
| 3c. 載入效能 | 瀏覽器 Performance API | 記錄殼顯示與 Python 就緒時間；模擬 Slow 4G 與離線各量一次 |
| 4. 端到端 | in-app 瀏覽器（本機）；Playwright（**需安裝，安裝前會先問你**） | 每個工作表操作一次、離線重新載入、匯出 → 清空 → 匯入來回測試 |
| 5. PWA 檢查 | `tools/check_shell.py` | 所有檔案都列在 `sw.js` 快取清單、版本號同步 |

- 每次驗證產生 `logs/verify-YYYYMMDD-HHMM.html`，記錄 commit hash、測試結果、修改過程
- 跑驗證前先確認 git 是乾淨的

## 5. 教學產出

## 8. 風險與不確定之處

| 風險 | 處理 |
|---|---|
| Pyodide 在手機上首次載入慢 | **已處理**：改用 MicroPython（約 0.23 MB）＋殼先顯示＋Web Worker＋預先快取 |
